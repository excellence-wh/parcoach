# PBL 工作流编排器（Parcoach Workflow Orchestrator）

Parcoach（亲导）项目的**主入口编排 skill**。它把「一个知识点 → 一份可交付的 PBL 教案文档/PPT」这条链路串起来，负责**决定顺序、判断当前阶段、调用正确的能力、交代清楚交接物**。它自己不做各环节的细节实现——那些由各自的 skill 负责。

## 定位与边界

- **编排层职责**：判断当前阶段 → 决定下一步 → 调用对应 skill → 校验交接物 → 推进到下一阶段。
- **复用而非重造**：澄清交给 `knowledge-point-clarifier`，导出交给 `pdf`/`pptx`/`html-ppt`。编排层**不重复**它们的规则，只做路由与衔接。
- **用户随时可跳出**：用户可在任意阶段中断、只取其中一段、或改方向。编排层按需推进，不强制跑完整流程。

## 阶段流水线

| 阶段 | 名称 | 调用/产出 | 进入条件 | 完成判据 |
|---|---|---|---|---|
| 0 | 路由 | 识别输入，决定是否走本流程 | 用户给知识点/主题，要求做教案 | 确认目标 = 产出 PBL 教案（含导出） |
| 1 | 澄清盘对 | 调用 `knowledge-point-clarifier` | 进入阶段0后始终先澄清 | 五项判据达成（定义/边界/对象/目标/约束），用户确认回放 |
| 2 | 生成教案 | 调用 `pbl-lesson-builder` | 阶段1已盘对 | 8 模块教案成型，且与交接物一致 |
| 3 | 导出交付物 | 调用 `pdf` / `pptx` / `html-ppt` | 阶段2教案成型 | 成功生成用户选择的交付文件 |
| 4 | 反馈迭代 | 调用 `pbl-feedback-iteration` | 阶段3交付或用户反馈 | 用户满意或完成本轮迭代 |

## 分阶段指引

### 阶段 0 — 路由
识别用户输入。若属于以下情形则启动本流程：
- 用户给出知识点/主题并要求做成 PBL 教案
- 用户明确说"帮我走全流程""从知识点做到 PPT""生成一套教案"
不属于（如只是问某个小问题、只要求澄清盘点）则**不启动**，按用户实际意图响应。

### 阶段 1 — 澄清盘对（交给 knowledge-point-clarifier）
- 启动 `knowledge-point-clarifier` 的逻辑，把知识点**盘对**。
- 交接物（handoff contract）必须齐全：**知识点的准确定义、边界、目标对象（年龄/场景/起点）、行为化学习目标、约束（时长/材料/限制）**。
- 用户确认回放后，阶段1才算完成，才进入阶段2。**不得跳过澄清直接写教案。**

### 阶段 2 — 生成 PBL 教案（交给 pbl-lesson-builder）
- 启动 `pbl-lesson-builder`，基于阶段1的交接物撰写**可直接落地**的 PBL 教案（8 模块：概述与驱动问题 / 学习目标 / 里程碑 / 引导策略 / 最终产出 / Rubric / 家庭课堂适配与分级 / 扩展）。
- 交接物：阶段1的五项结论 + 用户对交付的要求。撰写遵循黄金标准 PBL（PBLWorks）。
- 不重复教案撰写细节——细节实现归 `pbl-lesson-builder`。

### 阶段 3 — 导出交付物（交给 pdf / pptx / html-ppt，遵循 pbl-style-guide）
教案定稿后，询问用户**想要哪种交付形态**，再调用对应 skill。**无论选哪种，都必须遵循 `pbl-style-guide` 规范**，保证视觉与模板统一：
- **文档型教案** → 调用 `pdf`（或项目内文档规范）导出；用品牌 token（forest green #3E7C59 / 暖橙 #E8A13C）配色
- **演示型教案/上课用 PPT** → 调用 `pptx`（Office 风格）或 `html-ppt`（HTML 演示）
  - **html-ppt 强制**：引入 `styles/parcoach-theme.css` 作为唯一主题，**禁止**选用 html-ppt 自身的其它 36 个主题；优先复用其全 deck 模板承载教案，但 token 覆盖为品牌色
  - 三套（文档/html/pptx）的配色、字体、每节课卡片布局保持一致
- 若用户要其它（如 xlsx 评价表），也套用品牌 token。

导出前确认：遵循 `pbl-style-guide` 的固定页面顺序（封面→目标→概览→每节课→Rubric→适配→扩展）、每节课三问固定格式、且文件路径/命名合理。交出文件路径并说明打开方式。

### 阶段 4 — 反馈迭代（交给 pbl-feedback-iteration）
交付后启动 `pbl-feedback-iteration`：收集反馈 → 归因到对应阶段 → 回到该阶段精准修订（不改整份）→ 再确认。反馈归因表（澄清问题→阶段1、教案设计→阶段2、导出格式→阶段3）也由其负责。

## 交接物契约（handoff contract）

各阶段间必须显式传递以下信息，避免丢信息：
- **阶段1 → 阶段2**：澄清结论（定义/边界/对象/目标/约束五项）
- **阶段2 → 阶段3**：定稿教案（含封面信息：标题、课时、面向对象、时间）
- **阶段3 → 阶段4**：交付文件路径 + 生成方式 + 可调整点

## 编排原则

- **先澄清、再设计**：绝不跳过澄清直接生成教案。
- **每次只做当前阶段**：不越级（不要教案没定稿就导出）。
- **交给对的人**：细节实现委托给对应 skill，编排层不做重复实现。
- **面向老师/家长**：所有产出用家长/老师能直接读懂的话，孩子是学习主角，老师/家长是引导者。
- **就地取材、可落地**：材料尽量用家庭/教室常见物品，标注替代方案。
- **用户可控**：任意阶段尊重用户中断/改向；导出是可选项，先问清再生成交付文件。

## 场景示例

> **用户**：帮我全家流程做一份"恐龙灭绝的原因"的 PBL 教案，做成 PPT。
>
> **编排**：
> 1. （阶段1）启动澄清器盘对：「你说的'恐龙灭绝'具体指…」→ 盘出定义/边界/对象（孩子年龄）/目标/约束
> 2. （阶段2）据澄清结论撰写 PBL 教案：驱动问题、4 个里程碑、脚手架问题、Rubric、家庭/课堂适配
> 3. （阶段3）询问确认后调用 `html-ppt` 或 `pptx` 生成演示交付文件，给路径
> 4. （阶段4）交付后询问是否需调整
