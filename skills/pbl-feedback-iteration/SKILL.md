# 反馈迭代器（PBL Feedback & Iteration）

**阶段 4**：教案或交付物完成后，收集老师/家长的反馈，**定位问题、决定回到哪个阶段修订**。它不盲目重做，而是把反馈归因到具体环节，精准回到对应阶段。

## 触发

- 阶段2（教案）或阶段3（导出文件）交付后，用户给出反馈
- 用户表达"不满意 / 改一下 / 哪里不对 / 太简单 / 太难 / 换格式 / 再来一版"等

## 反馈归因（把反馈 map 到阶段）

收到反馈后，先判断它属于哪一类，再决定回到哪个阶段：

| 用户反馈 | 归因 | 回到阶段 |
|---|---|---|
| 「知识点理解不对 / 定义错了 / 边界搞错了」 | 澄清就没盘对 | 阶段1 `knowledge-point-clarifier` |
| 「孩子实际年龄/起点不对」「时长不够/太长」「场景不对」 | 澄清交接物错 | 阶段1 重新盘对 |
| 「目标不对，学完会不会 X」 | 目标没对齐 | 阶段1（重盘目标） |
| 「教案活动不合适 / 太简单 / 太难 / 缺某类活动 / 材料拿不到」 | 教案设计问题 | 阶段2 `pbl-lesson-builder` |
| 「驱动问题没意思」「Rubric 看不懂」「展示形式不符」 | 教案内容问题 | 阶段2 修订对应模块 |
| 「导出格式不对 / 排版乱 / 想换 PPT 或文档」 | 导出阶段问题 | 阶段3 `pdf` / `pptx` / `html-ppt` |
| 「整体思路要换」 | 大改 | 从阶段1或阶段2重来 |

## 流程

1. **先复述反馈**，确认理解无误（避免盘错方向就乱改）。
2. **归因**到对应阶段（用上表，举一反三）。
3. 若反馈模糊/有多种可能，**只问一个澄清问题**锁定方向（遵循"一次一问"）。
4. **回到对应阶段修订**：调用对应 skill，仅改受影响的部分，不无谓重写整份。
5. **再次交付 + 再次确认**：改动完成后回传给用户，确认是否还需继续调。

## 原则

- **不盲目重做**：反馈到哪就改哪，避免打回整份重做浪费。
- **找准根因**：先归因再动，避免"头痛医脚"。
- **一次一问**：反馈不清时只锁一个关键问题。
- **保留已对的部分**：只改受影响模块，其它保持。
- **控制迭代轮数**：连续 2–3 轮仍在同一点打转，提示用户是否要换个思路或降低预期，而不是无限重试。

## 完成判据

用户明确表示"满意 / 可以了"，或本轮调整达到用户预期，阶段4完成。可再问一句是否需要最终导出 / 交付。

## 衔接

本阶段是流水线最后一环；完成后流程回到可随时重启的状态（用户可带新知识点/新教案重新进入阶段0）。
