# PBL 教案生成器（PBL Lesson Builder）

**阶段 2**：把「已盘对的知识点」转成一份**可直接落地**的 PBL 教案。它**不负责澄清**——必须先由 `knowledge-point-clarifier` 完成澄清盘对，拿到五项交接物后本 skill 才接手。若输入的知识点尚未盘对，应退回澄清阶段。

**视觉规范**：本 skill 生成教案的**内容结构**；教案的**视觉/版式统一**由 `pbl-style-guide` 规范约束，生成与导出时都必须遵循——只使用规范中的品牌 token 与固定版式，禁止自定义视觉。

## 前置条件（handoff contract）

本 skill 开工前，必须已具备以下五项（缺失即请先澄清，不要编造）：
1. 知识点的**准确定义**
2. **边界**（什么算、什么不算 / 易混淆点）
3. **目标对象**：年龄 / 年级、场景（家庭 or 课堂）、人数、当前起点
4. **行为化学习目标**：学后能做什么 / 说清什么
5. **约束**：时长、材料/工具/场地限制、需避免的点

## 教案输出结构（8 模块，按序）

### 1. 项目概述
- 项目名称（围绕知识点、孩子能懂的有趣名字）
- **驱动问题**（Driving Question）：开放、真实、有挑战
- 对象 / 预估时长 / 场景 / 人数

### 2. 学习目标
- 知识目标（掌握什么）
- 能力目标（批判思维、沟通、协作、创造）
- 情感/态度目标

### 3. 分阶段里程碑（3–5 个阶段 = 3–5 节课）
每阶段（每节课）含：
- 阶段目标
- 具体活动/任务（家长/老师引导话术 + 孩子动作）
- 所需材料（就地取材，标注替代品）
- **问题设计**（每节课都配，见下方「每节课三问」）
- 阶段产出（推动最终产出）

#### 每节课三问（每节课必配，三类各 2–4 个）
每节课都给这三类问题，构成完整的问题链：
- **课前启发**（激活经验、建立联结、抛出好奇）：让孩子带着问题进场。例：「你觉得……和你的生活有什么关系？」「如果是你，你会怎么……？」
- **课中引导**（探究/思考脚手架，facilitator 提问，不直接给答案）：例：「你从哪里找到证据？」「如果……会怎样？」「两种做法差别在哪？」
- **课后小结**（回顾、整理、自我评价）：例：「今天你学到的最重要的一件事是什么？」「还有什么没弄明白？」「下次你会怎么做不同？」

问题要求：匹配年龄段与知识点边界；开放、探究式，不设唯一标准答案；孩子是回答主体，家长/老师据问题再追问。

### 4. 引导策略
家长/老师是 **facilitator** 不是讲解者。给 5–10 个「脚手架问题」示例（可作为各节课"课中引导"问题的总库）。**注意：每节课的问题已在模块3的「每节课三问」中逐节给出，这里给出跨课程通用的脚手架提问原则与示例作补充，二者不重复、互为呼应。**

### 5. 最终产出与展示
- 最终作品描述（海报 / 模型 / 演示 / 报告 / 视频…，贴合对象与约束）
- 展示方式（向家人/同学介绍，含 Q&A）

### 6. 评价 Rubric
维度（探究深度 / 作品质量 / 表达 / 协作）× 等级（优 / 良 / 待改进）。用孩子和家长都能懂的语言，强调"学到了什么"，不只打分。

### 7. 家庭/课堂适配 + 难度分级
- 家庭：单人改亲子协作；材料简化
- 课堂：分组建议、时间分配
- 低龄（简化）与高龄（加深）调整

### 8. 交互式习题集（至少 10 题）

每份教案必须生成**至少 10 道交互式题目**，让孩子能直接作答、即时反馈对错。题型以**选择题和判断题**为主（单选/判断，点击即反馈），每题包含：
- 题干（孩子能读懂的语言）
- 若干选项（选择题）或 对/错（判断题）
- **正确答案**
- **一句解释/反馈**（答对鼓励、答错点出原因——答错时不直接给答案，给提示引导再想）

题目要求：
- 覆盖整个教案的所有知识点与学习目标（不能只集中在某节课）；难度从基础到进阶，含 1–2 道挑战题
- 匹配年龄段与知识点边界
- **必须可交互作答**：点击选中后即时高亮正确/错误；判断题点对/错反馈。交互逻辑用**纯 HTML + 内联 JavaScript** 实现，不依赖 React/Next/任何框架
- 每题都有能帮助孩子理解的反馈文案，而非只判对错

> **交付形态（重要）**：本 skill 的最终教案交付物是**一份自包含的纯 HTML 文件**（`.html`），把全部内容（封面/目标/每节课三问/习题集/Rubric/适配/扩展）和交互式题目逻辑（内联 JS，含题目数据、作答、即时反馈、计分）打包在**单个文件**里，双击即可在浏览器打开使用，可独立分发、可被他人直接使用/上传到教案仓库。**不依赖本仓库的 web 站或 Next.js 路由。**
>
> **模板**：直接复用本 skill 目录下的模板 `templates/lesson-template.html` —— 它已内置品牌 CSS（内联）、交互题渲染与作答逻辑（纯 JS）、题目数据结构。生成时**复制该模板，按模板中 `=========== 填写区 ===========` 标注逐块替换内容**，确保结构、版式、交互逻辑统一且开箱即用。生成的 HTML 即阶段2的交付物。

### 9. 扩展与下一步
1–3 个延伸项目/话题，鼓励继续探究。

## 撰写原则

- **驱动问题必须是"真问题"**：不是"什么是 X"这种可检索的，而是"我们怎样用 X 解决/做出…"。
- **孩子是主角**：孩子动手、试错、提问；家长/老师引导。
- **跨学科**：尽量链接至少一个其它学科（数学/语文/艺术/科学/社会）。
- **就地取材**：优先家里/教室现成物品，给替代方案，照顾普通家庭。
- **尊重年龄**：语言、复杂度、自主度匹配年龄段；含分级调整。
- **忠实交接物**：时长、人数、场景、边界、目标都严格按阶段1盘对结果来，不擅自改动。
- **基于框架**：黄金标准 PBL（PBLWorks）驱动问题、持续探究、真实性、学生声音、反思、公开展示。

## 完成判据

教案齐备 9 模块、且与五项交接物一致、达到"家长/老师可直接照着带孩子做"的程度，即算完成。**必须满足两个硬条件**：
1. 每个阶段（每节课）已配齐「每节课三问」（课前启发 / 课中引导 / 课后小结）
2. 已产出**一份自包含纯 HTML 教案文件**，内含**至少 10 道可交互作答题目**（内联 JS，点击即时反馈对错）——该文件双击即用、可独立分发

两者缺一即视为未完成。完成后把这份 HTML 教案（含封面信息）作为交接物交给下一阶段。

## 衔接

定稿后可问：「教案已完成。需要我把它导出成文档 / PPT 吗？」——导出由 `pdf` / `pptx` / `html-ppt` skill 负责（阶段3）。
